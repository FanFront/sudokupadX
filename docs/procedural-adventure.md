# Procedural Sudoku adventures

The standard-library Python generator creates **four interconnected 9×9
Sudokus**, a 27×27 fog-of-war world and four linked boss puzzles.

**Every orange boss cell is an ordinary cell inside its chapter's 9×9 Sudoku.**
It belongs to a row, column, and 3×3 box. The generator does not place
separate gate cells outside the Sudoku grid.

## Generate and test

```bash
python3 scripts/generate_adventure.py --seed 20261102
python3 -m unittest discover -s tests -p 'test_generate_adventure.py'
npm test
```

Outputs go to `public/puzzles/generated/` and are regenerated by npm
dev/build/test, including the Android build. Open **Library → The Four Gates
— Generated Adventure** or visit `?puzzle=generated-adventure-1`.

## Mathematical guarantee: the boss cell cannot be solved from the map

For each 9×9 grid, the generator first creates a unique standard Sudoku
with mutually consistent 3×3 overlaps. It then removes a *pivotal given*
from **inside** that grid to become its orange BOSS cell. Selection accepts
a cell only if BOTH conditions hold:

- **Without the boss digit:** the Sudoku admits at least two solutions,
  **even after providing the correct values of every overlapping cell
  shared with every other grid**. The alternative solutions necessarily
  disagree about the boss cell, because the puzzle was unique with that
  clue present. This also proves that solving all the *other* map grids
  cannot reveal this missing value through standard Sudoku logic.
- **With the boss digit:** the grid has exactly one solution, including
  its previously ambiguous cells.

The main world has a unique solution when all four boss answers are given.
Conversely, withholding any *one* boss value keeps at least two valid
global solutions even if all other boss answers and grid overlaps are known.

Each linked boss is generated as a unique 9×9 Sudoku. Its full 81-digit
solution is hashed together with its ID, seed and a version label. The
generator searches for a boss whose reward matches the required digit in
the main grid. **No single boss cell, including R5C5, is privileged.**

A solution-counting backtracking solver verifies classic 9×9 uniqueness
and ambiguity, **but it is not used to decide whether a puzzle is playable**.
Every boss must also be solved completely by a separate no-guessing
human-logic solver. It accepts naked and hidden singles, locked candidates
(pointing/claiming), naked pairs, hidden pairs, and naked triples. It cannot
assume a number, explore a case, or backtrack.

The generator rejects boss puzzles that this bounded technique set cannot
finish, even if they have exactly one mathematical solution. It also requires
an early, meaningful non-single deduction (within the first 25 logic steps)
and 1–5 non-single elimination steps overall, favoring a recognizable
**aha moment** over long speculative chains. This is a concrete upper bound
on required techniques, not a claim that all humans find the puzzle easy.

## Playable fog progression

The first chapter no longer displays all 81 cells. The generator builds a
**verified logical sequence** before deciding what to reveal. Each chapter
starts with a deliberately small set of visible givens and one deducible
empty cell. Filling that cell correctly reveals nearby cells plus any
additional clues required to make the next planned Sudoku deduction.

For every step, a Python verifier reproduces the entire process using
**only the currently visible givens and values already entered correctly**
and confirms that the next cell is an immediate naked or hidden single.
It does *not* treat hidden clues as known. After three logically deducible
steps, the embedded boss cell is revealed (but still cannot be filled without
defeating the linked boss). After its reward is entered, the verifier checks
that the rest of the grid can be completed without guessing and that every
cell eventually becomes visible. Generated puzzles fail validation if this
visible-only path stalls.

To make this feasible, the generator can add a small number of further
classic Sudoku givens, but only if they preserve the essential ambiguity of
each boss cell—even with all neighboring overlaps fully solved. This makes
the **main map an exploration puzzle**, while the four independent bosses
remain intended to be difficult. The map's guarantee is a complete singles-based path; the bosses have
their own complete deduction proof using the bounded techniques above.
Neither guarantee proves that every possible player-entered ordering
will avoid temporary dead ends.

Following the original Sudokuvania model, correctness-based rules typically
illuminate neighboring cells, with occasional nonlocal clue reveals needed
for continued deductions. Completing a boss unlocks only the *starter pocket*
of the next 9×9; the remainder must be explored by solving.

## Player progression

1. Select the highlighted orange boss cell **inside** a visible chapter
   to open the linked boss. Ordinary chapter cells may also provide the link.
2. Solve the entire boss. Its completion message awards the missing
   Sudoku digit derived from the whole completed boss grid.
3. Return to the map and enter that digit **into the highlighted Sudoku
   cell itself**. It participates in ordinary row, column, and box rules.
4. Entering the correct value after clearing the boss reveals only the
   next chapter's small initial patch. Solve its visible deductions to keep
   pushing back the fog. The fourth boss provides the final missing digit.

The game intentionally blocks placing a value in the boss cell until
its linked boss is cleared, but the stronger guarantee is mathematical:
without its reward, the cell isn't uniquely derivable from standard
Sudoku or from the other connected grids.

Progress is stored with reward version **v3**. Old v1/v2 boss-clear flags
cannot unlock newly generated puzzles. Other SudokuPad puzzle formats and
their original fog mechanics are unaffected.

## Limitations

- SudokuPadX currently stores authored solutions and boss rewards in its
  puzzle files to verify player inputs. The guarantee concerns **legitimate
  Sudoku deductions**, not inspecting the package, guessing repeatedly,
  or exploiting a correctness checker.
- The bosses are independent classic Sudoku challenges, not automatically
  constructed killer/arrow/thermo puzzles. Their completed solutions
  supply the mathematically necessary missing values.
- Bosses now require both uniqueness and a complete human-style logical
  solving path. The proof for each generated boss is saved to
  `public/puzzles/generated/validation.json` as `boss_logic_trace`,
  alongside per-technique counts. These checks do not guarantee subjective
  elegance, visual presentation, or a particular player's experience.
- Puzzles needing more advanced techniques, such as X-Wing, chains,
  forcing nets, or contradiction-based trial, are deliberately rejected
  rather than labeled merely "hard".
- Updating the generated puzzle while retaining its IDs can invalidate
  existing local progress. Start this adventure fresh after upgrading.
- Cross-puzzle boss-completion flags are stored locally and are not yet
  included in ordinary SudokuPadX checkpoint transfers.
