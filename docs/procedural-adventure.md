# Procedural Sudoku adventures

The standard-library Python prototype generates four overlapping 9×9 Sudoku
grids on a 27×27 map and four uniquely solvable linked bosses. **Unlike the
first prototype, the bosses are now mandatory for progression.** The reward
cell from each boss is not a normal Sudoku cell of the world map.

## Run

```bash
python3 scripts/generate_adventure.py --seed 20261102
python3 -m unittest discover -s tests -p 'test_generate_adventure.py'
npm test
```

Generated assets live in `public/puzzles/generated/`. The default seed is
regenerated by npm dev, build and test scripts. Open **Library → The Four Gates
— Generated Adventure** or `?puzzle=generated-adventure-1`.

## How the new boss gates work

1. Enter any visible cell inside a chapter to open its associated boss.
2. Solve the boss completely. Its completion dialogue reveals the value of
   **R5C5**, which is never given in that boss's grid.
3. Return to the world map. Find the orange **BOSS gate** beside that chapter.
   It lies outside all four standard Sudoku grids. Enter the boss's R5C5
   value in this marked cell.
4. The next chapter is revealed only when BOTH (a) the boss is registered as
   completed and (b) the correct reward digit is entered in its gate. Repeat
   for three chapters. The fourth gate is needed to complete the full map.

The gate has no row, column, or 3×3 box constraint, so the main map cannot
logically reveal its digit. In contrast, the old puzzle had a standard
cellvalue fog trigger which the player could solve without visiting a boss.

Boss completions persist in local storage, keyed to the adventure ID, seed and
boss ID. When returning to the map or restoring progress, SudokuPadX combines
these flags and gate values with Rust's initial fog. Cross-chapter unlocks
occur strictly in order. All other SudokuPad puzzle formats retain their
original fog logic.

## Construction and verification

Each successive map grid overlaps the previous one in a full 3×3 block.
Solutions are digit-remapped to agree. Ordinary givens avoid overlap cells.
Grid four has one solution. Grids one through three admit multiple local
solutions before they receive the following shared block, but have one
solution once those digits are known. This proves that the **Sudoku grids**
have one globally consistent solution.

Four standalone bosses are independently unique. Low givens and resistance
to naked/hidden singles are used as preliminary difficulty filters; these
are NOT calibrated human hard ratings.

The generator checks that every gate is outside all Sudoku grids, that no
gate contains a given, that each boss center digit is initially blank, that
the world solution matches its boss's reward digit, and that each chapter
reveals 81 cells plus the next gate. The JS tests check progression order,
completed-boss persistence, and that an uncleared boss cannot unlock fog.

## Known limitations

- The boss reward (R5C5) can sometimes be logically deduced *within the
  boss* before the whole boss is complete, but entering it in the map gate
  is blocked until completion. A future generator may require a custom
  mechanic that genuinely uses the boss's entire completed grid.
- The bosses are classic Sudoku; killer, arrow, thermo and other variant
  constraint generation remains future work.
- Logical deductions and adventure pacing are not yet human-difficulty rated.
- Changing the random seed with the same generated puzzle IDs may invalidate
  existing saves. Export progress before changing seeds.
- Boss completion flags are local device/browser data. Transferring an ordinary
  checkpoint does not currently transfer all cross-puzzle completion flags.
